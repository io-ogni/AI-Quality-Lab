## Change 1: Sandbox Scenario-Specific Form State

**Location:** Sandbox > Criteria Form section

**Problem:** When switching scenarios, the form fields kept showing content from the previous scenario.

**Fix:** Each scenario has its own form state:

```javascript
// Store form state per scenario
const [formStateByScenario, setFormStateByScenario] = useState({});

// While working (not yet passed):
// - Switching to another scenario → current scenario's fields PRESERVED
// - Switching back → user sees what they previously wrote

// After passing:
// - User passes a scenario (validation successful)
// - User navigates away (to another scenario OR another page)
// - THEN clear the fields for that passed scenario

function onNavigateAway(fromScenarioId) {
  if (formStateByScenario[fromScenarioId]?.passed) {
    setFormStateByScenario(prev => ({...prev, [fromScenarioId]: null}));
  }
}
```

## Change 2: Three-Layer Validation Architecture for Sandbox

**Location:** Sandbox > Eval Design Scoring Logic

**Problem:** Prompt-only guardrails can be ignored by LLM or bypassed via prompt injection.

**Fix:** Added code-level validation BEFORE and AFTER LLM call:

```
User submits
     │
     ▼
┌─────────────────────────────────────────────────────────────┐
│ LAYER 1: PRE-VALIDATION (Code — runs BEFORE LLM)            │
│ • Garbage detection (too short)                             │
│ • Copy-paste detection (criteria → example)                 │
│ • Identical examples detection                              │
│ • Format detection (examples look like criteria lists)      │
│ • Offensive content detection (TensorFlow.js or API)        │
│                                                             │
│ If FAIL → Return immediately, DO NOT call LLM               │
└─────────────────────────────────────────────────────────────┘
     │
     ▼
┌─────────────────────────────────────────────────────────────┐
│ LAYER 2: LLM EVALUATION                                     │
│ Semantic evaluation of criteria quality                     │
└─────────────────────────────────────────────────────────────┘
     │
     ▼
┌─────────────────────────────────────────────────────────────┐
│ LAYER 3: POST-VALIDATION (Code — runs AFTER LLM)            │
│ • Override if LLM missed offensive content                  │
│ • Override if LLM scored copy-pasted text too high          │
│ • Recalculate overall score if needed                       │
└─────────────────────────────────────────────────────────────┘
```

## Change 3: New Automatic Fail Conditions for Examples

**Location:** Sandbox > Judge Prompt > AUTOMATIC FAIL section

**Added these new rules:**

### 4. Example Format Detection
- Examples must look like BOT RESPONSES, not criteria lists
- If example contains bullet points (-, •, *) or numbered lists → FAIL (score 1/5)
- If example is copy-pasted from Criteria field → FAIL (score 1/5)

### 5. Offensive/Inappropriate Good Example
- If "Good Example" contains insults, profanity, hostile language → AUTOMATIC FAIL
- A "Good Example" that says "you are an idiot" is NEVER acceptable
- Flag prominently, not just in "To Improve"

### 6. Cross-Field Validation
- Bad Example = criteria copy-pasted → Score 1/5, "This is not an example"
- Good Example = criteria copy-pasted → Score 1/5
- Good Example would realistically be bad → Flag: "Your 'good' example looks like the 'bad' example"

**Added explicit examples in prompt:**

```
### EXAMPLE OF OFFENSIVE GOOD EXAMPLE (should score 1/5):
- Criteria: "be empathic, offer refund, stay professional"
- Good example: "you are an idiot"
- Bad example: "I apologize..."
→ CRITICAL FAILURE. Cannot pass with offensive "good" example.

### EXAMPLE OF COPY-PASTED CRITERIA (should score 1/5):
- Criteria: "- be empathic\n- offer refund"
- Bad example: "- be empathic\n- offer refund"
→ This is not an example — user pasted their criteria.
```

## Change 4: Privacy-First Content Moderation

**Location:** Sandbox > Pre-validation > Offensive Content Detection

**Problem:** Regex blocklists don't catch variations like "d1ck", "fück", "a$$".

**Solution:** Layered approach with TensorFlow.js as primary (no API calls):

### Option A: TensorFlow.js Toxicity Model (RECOMMENDED)

```bash
npm install @tensorflow/tfjs @tensorflow-models/toxicity
```

```javascript
import * as toxicity from '@tensorflow-models/toxicity';

// Load once at app start
let toxicityModel = null;
toxicity.load(0.85).then(model => {
  toxicityModel = model;
});

// In pre-validation:
const predictions = await toxicityModel.classify([criteria, goodExample, badExample]);

// Check for toxic categories: severe_toxicity, toxicity, insult, threat, obscene
for (const prediction of predictions) {
  if (prediction.results[i].match) {
    // Text flagged
  }
}
```

**Benefits:**
- Runs 100% client-side (browser)
- No API calls, no data sent anywhere
- Catches variations (trained on real data)
- Free
- ~15MB model download (one-time, cached)

### Option B: API Fallback (if TensorFlow.js unavailable)

## Change 5: Pre-validation Code

**Full implementation added:**

```javascript
async function preValidateSandboxSubmission(criteria, goodExample, badExample) {
  const errors = [];
  const warnings = [];

  // 1. GARBAGE DETECTION
  if (criteria.trim().length < 20) errors.push({field: "criteria", issue: "too_short"});
  if (goodExample.trim().length < 10) errors.push({field: "good_example", issue: "too_short"});
  if (badExample.trim().length < 10) errors.push({field: "bad_example", issue: "too_short"});

  // 2. COPY-PASTE DETECTION
  if (similarity(goodExample, criteria) > 0.8) errors.push({field: "good_example", issue: "copy_paste"});
  if (similarity(badExample, criteria) > 0.8) errors.push({field: "bad_example", issue: "copy_paste"});
  if (similarity(goodExample, badExample) > 0.9) errors.push({field: "both", issue: "identical"});

  // 3. FORMAT DETECTION (examples shouldn't look like bullet lists)
  const bulletPattern = /^[\s]*[-•*]\s+/m;
  if (bulletPattern.test(goodExample)) warnings.push({field: "good_example", issue: "looks_like_criteria"});
  if (bulletPattern.test(badExample)) warnings.push({field: "bad_example", issue: "looks_like_criteria"});

  // 4. OFFENSIVE CONTENT DETECTION
  // Use TensorFlow.js, or API fallback, or regex (see Change 4 above)

  // 5. RETURN
  return {
    valid: errors.length === 0,
    errors,
    warnings,
    forcedScores: errors.length > 0 ? { overall_score: 1, passed: false } : null
  };
}

function similarity(a, b) {
  const wordsA = new Set(a.toLowerCase().split(/\s+/).filter(w => w.length > 2));
  const wordsB = new Set(b.toLowerCase().split(/\s+/).filter(w => w.length > 2));
  const intersection = [...wordsA].filter(w => wordsB.has(w)).length;
  const union = new Set([...wordsA, ...wordsB]).size;
  return union > 0 ? intersection / union : 0;
}
```

## Change 6: Post-validation Code

**Added code to override LLM if it missed issues:**

```javascript
function postValidateLLMResponse(llmResult, criteria, goodExample, badExample) {
  // Override if LLM gave high score to offensive good example
  if (llmResult.scores.good_example.score > 2) {
    if (/idiot|stupid|moron|fuck/i.test(goodExample)) {
      llmResult.scores.good_example.score = 1;
      llmResult.scores.good_example.feedback = "CRITICAL: Offensive language.";
    }
  }

  // Override if LLM gave high score to copy-pasted bad example
  if (llmResult.scores.bad_example.score > 2) {
    if (similarity(badExample, criteria) > 0.7) {
      llmResult.scores.bad_example.score = 1;
      llmResult.scores.bad_example.feedback = "This is not an example — you pasted criteria.";
    }
  }

  // Recalculate overall
  const avgScore = (specificity + relevance + completeness + good_example + bad_example) / 5;
  llmResult.overall_score = Math.round(avgScore);
  llmResult.passed = llmResult.overall_score >= 3;

  return llmResult;
}
```

- Visual diagram showing three layers:
  1. CODE PRE-VALIDATION (garbage detection, copy-paste, offensive content)
  2. LLM EVALUATION (semantic matching, quality judgment)
  3. CODE POST-VALIDATION (hallucination check, override bad scores)

### Section 3: What's Deterministic vs AI
Table showing who does what:
| Task | Who Does It | Why |
|------|-------------|-----|
| Check if input is too short | Code | Simple rule, 100% reliable |
| Detect copy-pasted text | Code | String comparison, no AI needed |
| Detect offensive content | Local AI model | Catches variations without API calls |
| Match "polite" to "professional" | LLM | Requires semantic understanding |
| Judge if criteria are complete | LLM | Requires domain knowledge |
| Verify LLM didn't hallucinate | Code | Check if claimed text exists in input |
| Calculate final score | Code | Math, not judgment |

### Section 4: Challenges Mode — Deterministic Matching First
- Explains synonym tables for the 30 fixed challenges
- Why: Instant, free, 100% reliable, consistent

### Section 5: Content Moderation — Privacy First

### Section 6: Why This Matters for Your Work
Key lessons:
1. Don't trust LLMs alone — validate
2. Use code for what code does best
3. Use AI for what AI does best
4. Validate inputs BEFORE the LLM
5. Validate outputs AFTER the LLM
6. Privacy matters — use local models when possible
